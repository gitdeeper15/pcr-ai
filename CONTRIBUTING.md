# Contributing to Research II

**The Production and Control of Representations in Artificial Intelligence — Research II: A Conceptual Architecture, Authority Structure, Representation Lifecycle, and Research Protocol**

---

## Status

This project is a **prospective structural research protocol** (`v0.1`). Three of the four foundational documents remain pending adoption. No empirical work has been performed.

Contributions at this stage are welcome in:

- **Literature review** (Section 2): Situating the architecture against platform governance, media sociology, algorithmic accountability, ANT/infrastructure studies, and HAI research.
- **Document adoption review**: Critical review of Authority Structure (v0.1), Representation Lifecycle (v0.1), and Research Questions (v0.1).
- **Methodological scope** (RQ-D2): Proposals for whether families A–C should be examined analytically, empirically, or both.
- **Documentation**: Clarifying the manuscript, adding examples, or improving figure quality.

**Not accepted at this stage:**

- Empirical claims presented as findings (no empirical work has been performed).
- New architectural commitments that bypass the sequential adoption discipline.
- Integration of Research I and Research II findings (RQ-D1 is deferred).
- Changes to the research questions without a documented rationale.

For extensions, open an issue first to discuss scope.

---

## Reporting Issues

Open an issue with:

- A one-sentence description.
- The affected file (e.g., `README.md`, `PUBLICATION/Production_Control_Representations_In_Artificial_Intelligence.pdf`).
- A minimal reproduction or screenshot.
- Expected vs. actual behavior.

---

## Submitting Changes

```bash
git checkout -b feature/short-description
# make changes
git commit -m "feat: short description"
git push origin feature/short-description
```

Then open a pull request. Each PR should address one concern.

Code Standards

Language Standard
Python PEP 8, black (88 chars), isort, flake8
Markdown markdownlint (MD013 disabled)
YAML yamllint

Reproducibility: every documentation change must preserve the sequential adoption discipline (Section 8.1) and the negative commitments (Sections 3.7, 4.9, 6.6).

Data Provenance

All figures and diagrams are original to this project. No third-party imagery was used. The four conceptual diagrams (five functions, canonical lifecycle, five authorities, five paths) were constructed from the architectural description in the manuscript.

Review Process

· All changes are reviewed by the maintainer (Samir Baladi).
· Changes to the manuscript, figures, or document status require explicit documentation in CHANGELOG.md with rationale.
· Adoption of any pending document requires an explicit version increment.
